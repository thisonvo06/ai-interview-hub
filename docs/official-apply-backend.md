# 官网投递、后端可靠性与前端改版

## 使用方式

岗位详情的“前往企业官网”在新标签页打开企业配置的招聘链接。登录个人账号时，会在“我的求职”中创建一条官网笔记；重复打开同一岗位不会重复创建。访问不会上传简历、创建企业候选人或发送企业通知。

用户实际完成官网提交后，点击“确认投递 / 更新进度”，手动记录已投递、面试、Offer、未通过或结束跟进，并填写备注。时间线与首页统计使用这些记录。官网状态无法自动同步，用户需要按官网或 HR 反馈更新。旧平台申请保留在“历史平台申请”标签中，新平台申请接口返回 409，引导官网投递。

企业新建、编辑及复制岗位时，可配置 `official_apply_url`。链接须为 HTTPS，不接受带凭据、本地地址、IP 地址或非标准端口。发布审核前必须配置有效链接，管理员审核列表能查看入口；域名是否属于该企业或其授权招聘系统仍需人工核对。服务端不抓取官网，不代为提交。

现有演示企业仅补充官方招聘列表入口，不保证演示岗位在官网实际开放，也不会覆盖企业已有的自定义链接：

## 权限与隐私

- REST 校验 access token 类型、账号状态、有效会话及撤销状态；refresh 与 access 使用同一会话标识。退出后，两者均失效。
- 找回密码接口不再在 SMTP 缺失或发送失败时返回、记录重置令牌；重置链接使用后失效，修改或重置密码撤销原有会话。部署时可配置 FRONTEND_BASE_URL 为邮件链接入口，未配置 SMTP 时联系管理员处理。
- WebSocket 在接受连接前鉴权，只接受 90 秒、绑定通道和资源的票据，连接后持续检查原登录期限与会话状态。通知前端也已使用票据。
- AI 配置修改、连接测试及用量数据仅平台管理员可访问；普通用户不能读到服务地址或密钥掩码。测试新地址时必须明确填写新密钥。
- 上传文件默认私有，通过鉴权下载接口访问；校验文件所属、路径和 10 MB 上限，响应 MIME 按扩展名确定，并设置 `nosniff` 与 `no-store`。此处没有加入病毒扫描或内容格式检测。
- 简历只能关联本人上传文件；个人训练报告仅本人可见，企业查看报告须有有效企业成员身份与企业授权范围。正式招聘面试从本人企业邀请进入。

## 面试提交、评分与恢复

`POST /api/v1/interviews/{id}/answer` 现在必须带 `question_id` 与 `request_id`。同一作答重试应复用原请求 ID 与原答案；同一 ID 被用于不同内容或题目返回 409。前端在 sessionStorage 保留未完成请求，成功后清除。可选 `expected_version` 用于显式版本校验。

REST 与 WebSocket 共用作答服务。数据库条件更新与处理租约保证同一时间只有一个提交处理者；答案先保存，再调用模型；评分、追问、题目推进及可重放响应在一次事务内提交。暂停、继续及终态由服务端检查，暂停时停止计时。

逐题评分校验六维完整性与数值范围。专业、相关性、完整性、逻辑、深度、沟通权重分别为 30%、20%、15%、15%、15%、5%；超时由服务端扣分。报告分数由已保存的逐题评分汇总，题目难度权重为 EASY 1、MEDIUM 1.2、HARD 1.5。报告雷达显示实际维度，不补默认高分。

评分保存成功后，即使报告生成失败也不丢失答案。报告页提供重试；报告与学习更新分别记录状态，学习更新失败时重试不重复评分、报告或能力历史。`finish` 可用于恢复报告，仍受用户所有权与终态限制。

模型结果携带实际来源（REAL、MOCK、MOCK_FALLBACK、RULE 或 UNKNOWN）、模型、提示与评分版本，并记录调用关联信息。正式企业评分和报告拒绝模拟回退。个人模拟数据在报告页明确提示，模拟及来源未知的评分不写入新的正式技能证据。简历解析在模拟回退时保留文件并报错，不将虚构经历写入简历。

能力更新按实际题目技能分组保存，证据包含题目、评分记录和样本数。历史旧记录保留，并没有重新生成或清除原有演示分数。学习任务按标题与能力去重合并，保留完成、跳过状态及进度。

## 统计与前端

技能覆盖率取简历技能与岗位技能标签的交集；它是标签覆盖比例，不代表录用概率。缺少数据时返回空值。候选人详情展示投递时保存的简历快照，移除固定学校、项目、优势与建议内容。

企业分析按所选日期范围使用真实申请、流转历史与录用记录。未采集的浏览量和渠道不编造。AI 用量统计区分实际调用来源、Token、成功率及延迟。个人首页的本周时长取最近七天实际作答秒数；官网投递数量来自用户确认，成长曲线不插入虚构起点。

前端采用暖白纸面、墨绿重点色、宋体标题与细分隔线。首页使用杂志封面和文章目录式岗位列表；个人空间、登录、岗位详情和投递页统一视觉。导航、侧栏与主要内容做了手机适配；尊重减少动效设置。所有路由按需加载，图表代码在需要时加载。

## 启动与迁移

后端启动自动执行 Alembic `upgrade head`。本次新增 `0001_legacy`、`0002_reliable_backend`、`0003_official_entries`、`0004_job_search`、`0005_job_search_identity`，兼容旧 SQLite 数据库并添加追踪、来源、处理状态及私有求职计划。原先每次启动重复执行的旧数据清洗移入一次性迁移。迁移保留业务记录，运行前建议按项目原有方式保留数据库备份。

更新后重启后端并刷新前端。旧的、不带有效会话标识的登录凭证需要重新登录；原环境配置与启动入口继续可用。若手动升级，在 backend 目录运行 `python -m alembic upgrade head`。

验证命令：

```powershell
# 在 backend 目录（先安装 requirements-dev.txt）
python -m pytest tests -q --disable-warnings -p no:cacheprovider

# 在 frontend 目录
npm run build
```
