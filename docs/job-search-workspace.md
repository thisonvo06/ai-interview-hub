# 求职计划工作台

本次结合本地 `D:\ai-job-search-work\ai-job-search` 的岗位筛选、准备材料、投递跟进与技能缺口工作流，在现有 FastAPI + Vue 系统中增加用户独立的求职计划。参考项目是一套单用户命令与文件工作流，本次按现有账号、数据库与网页交互重新实现。

## 页面入口与使用顺序

个人空间的“求职计划”进入 `/personal/job-search`。岗位详情和官网投递笔记中的“加入求职计划 / 制定求职计划”可将平台岗位放进计划；也可以粘贴外部岗位的 JD、公司、职位、城市、技能标签及截止日期。来源链接用于用户自行打开，不在服务端抓取。

1. 收集岗位：相同用户重复保存同一机会时返回原记录，保留之前的备注、分析和进度。不同用户的收藏互不影响。
2. 选择自己的简历并分析：显示实际技能标签覆盖、匹配证据、缺失技能及条件检查。没有足够数据的项目显示“未知”，覆盖率不代表录用概率。
3. 生成准备包：整理简历亮点、求职信草稿、跟进草稿、面试问题和 STAR 素材。可以在页面修改草稿、复制或下载 Markdown；页面修改是本地草稿，不改写原简历。
4. 到来源官网完成实际提交，再手动更新计划状态。记录面试反馈、下一次跟进日期，按企业渠道实际情况更新。
5. 查看多个活跃岗位反复出现的技能缺口，并进入现有学习路线继续训练。

## 数据与边界

- 工作台分析与准备包的来源标记为 `RULE`，使用确定性规则和本人简历已有素材。不会将模板称为模型生成或经过企业验证，也不编造项目业绩、公司背景、学校或录用概率。
- JD 是用户保存的材料；即使含有命令式文本，也不会执行其中的指令、访问附带链接或运行脚本。
- 岗位信息、分析和准备材料只允许本人个人账号读写。生成的准备包保存生成时的简历依据；之后编辑原简历不会悄悄改变已生成的内容，重新准备才会更新。
- 同公司官网招聘列表可能服务多个岗位，不能仅凭列表 URL 合并。去重保留中文信息，并结合岗位身份及城市；URL 去除追踪参数但保留业务参数。
- 更新使用记录版本，另一处页面先更新时返回冲突，需要刷新。截止与跟进按中国区日历日期（UTC+8）比较，7 天内提示临近截止；过去只提示“已过期”，不推断企业拒绝或自动关闭记录。
- 初次确认已提交后默认安排 10 天后的跟进；单纯收藏、打开官网、编辑备注、分析或生成草稿不会算联系过企业。“我已自行跟进”才记录实际联系，最多两次；终态结束提醒。
- 官网笔记与求职计划分别记录，不双向同步。官网笔记保存平台岗位的官网访问/投递事实；求职计划还可收集外部岗位和准备材料。两个页面的数量不能简单相加作为总投递量。
- 技能缺口来自岗位明确技能标签与所选简历的差集；拒绝但未说明原因，不会被推断成某项技能不足。反馈原文由用户记录，供复盘使用。

## 本次未引入的外部依赖

参考项目包含丹麦招聘网站 CLI、LinkedIn 搜索、Notion/Gmail 同步与 LaTeX 申请材料。本次先实现可在现有系统直接使用的工作流。没有运行参考仓的抓取工具、导入其个人档案、读取邮箱或自动投递；PDF 排版与外部账户同步也没有作为此工作台的已完成能力。

## 后端接口

所有路径带 `/api/v1` 前缀，响应沿用 `{code,message,data}`，需要有效个人账号会话。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/personal/job-search` | 列表、摘要、缺口 / 手动收集 |
| POST | `/personal/job-search/from-job/{id}` | 从已发布的平台岗位收集 |
| GET / PATCH / DELETE | `/personal/job-search/{id}` | 本人详情、版本更新、删除 |
| POST | `/personal/job-search/{id}/analyze` | 根据本人简历分析 |
| POST | `/personal/job-search/{id}/prepare` | 整理准备材料 |
| POST | `/personal/job-search/{id}/follow-up` | 确认用户已自行跟进 |

新增 Alembic `0004_job_search` 与 `0005_job_search_identity`，后端重启时自动升级。后一个版本约束同一用户与同一平台来源，桥接手动收集和平台入口时保留原有材料、备注和状态。原来的官网投递、面试及历史记录继续保留。

## 验证

提交前完整后端回归 68 项通过，包含求职工作台的 32 项用例，覆盖两入口去重、真实并发、外键删除、联系日期边界与重复迁移。前端类型检查与生产构建通过。浏览器使用全新的临时数据库、示例简历和模拟模式，验证了桌面/390 px 手机布局、匹配依据、反馈保存、跟进确认、未保存草稿保护及平台入口复用原计划。没有使用或修改用户的真实求职数据。

Markdown 下载的客户端实现已通过构建，但内置预览浏览器未返回下载事件，本次没有确认文件落盘；普通浏览器中的下载仍需实际确认。
